已确认规则与实施边界

已确认：带「试驾排程」标识就创建排程工单；不再将弱意向、缺项或无份额自动转线索作为此场景的默认分支。返回数据一般包含日期，本次不新增缺日期处置规则。

范围：通知规则沿用现状，本次不新增。建单成功与同步成功分别记录；真实排程与同步接口仍需联调验证。

场景说明

对应「培育策略 → AI外呼配置 → 滞留数据配置」。发起 AI 外呼请求时，若通道因并发问题暂不能承接，任务进入滞留队列。此处的「滞留数据处理设置（包含重拨数据）」定义允许处理的星期与时段；非合法时段保持等待，进入合法时段后再按通道可用情况继续处理。

流程编号：FLOW-005关键判断：通道并发可用性、合法处理星期与时段AI外呼请求 → 并发受限入队 → 时段判断 → 通道可用后处理状态：业务口径已确认；真实队列调度待服务验证
配置含义：合法处理时间是队列任务允许执行的时间窗口，并不承诺进入时段即全部处理成功。通道仍受并发限制时，任务继续等待。

已确认规则与实施边界

滞留原因：AI外呼请求因通道并发问题暂时无法执行，任务进入滞留队列。
时段控制：「滞留数据处理设置（包含重拨数据）」维护合法处理的星期与时间段；非合法时段不处理，任务继续等待。进入合法时段后仍须满足通道可用条件。
处理范围：滞留任务与已有规则产生的重拨数据共用本设置的时间窗口；本设置不新增重拨触发条件。
实施边界：图中等待与继续处理表达业务条件，不规定调度轮询频率、队列优先顺序或并发额度。真实排队、通道状态读取及调度恢复须由服务端实现并验证；本次仅修正文档及界面说明。

场景说明

普通对象由 Agent 生成建议，系统按接收时生效的来源形成执行方案；运营保留原始建议作对照，可调整最终分配并逐条审核发布。只有收到 DCC 成功回执后才切换生效规则，每次成功发布留存独立正式版本及整套快照。

五项动作：线索状态、回访结果、异常原因、回访描述、意向级别，均读取本次已保存配置快照。默认值分别为休眠失联、休眠失联、三天四次无法接通、多次联系无人接听、L；实际值以管理员确认保存的配置为准。
正常放行：未配置区间、无有效评分、读取异常、未命中时沿用原流程；无等待六分钟、无轮询、无历史补改。合法零分按有效评分参与判断。仅人工选择提示或返回修改不产生保存成功记录。
厂商回流同步：厂商回流同步在同步前兜底：本次操作已完成转换的线索沿用已保存结果，不重复查分或覆盖；其余仅在回访结果为「无人接听下发」时查询预评分。命中后按本次统一配置更新DCC五项字段，保存成功后再同步厂商；保存失败不发送，同步失败保留DCC已保存结果。转换标记按本次操作和线索关联，不永久跳过后续独立操作。
同步边界：DCC 完成字段转换后继续既有主机厂同步，不能把转换当作剔除下发记录。保存失败不发送，保存成功与同步成功分开显示；主机厂最终处理依其接口约定，需正式联调验证。
记录口径：预评分转换记录包含六类来源和已转换、未命中、无分、处理失败；保存字段前后值、评分、规则配置版本、实际入口。筛选用任务编号／线索编号，下发批次仅关联批量来源；DEMO记录仅供演示。
