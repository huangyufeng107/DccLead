线索分派策略｜产品方案 V0.7

面向 DCC 培育平台的 Agent 智能生成分派策略方案（评审稿）

当前阶段：方案评审版策略生成：Agent 草案审核通过：单条提交 DCC 发布更新时间：2026-10-21
一句话结论：数据组批量提供线索明细，或由 Agent 按授权直连数据组库表查询已结算数据，并交给 Agent分析；Agent整理分析后输出可供业务系统自动创建规则的结构化建议。业务系统负责接收、兜底校验、审核和发布。AI总比例内的外呼类型由运营选择单一类型或关联已有 AI 内部比例配置，审核后以对象规则新版本发布。

1. 背景与目标

现状是人工定期查看《NEV 总部培育渠道核心日报》，清洗“人工”场景后计算效果、排名，再手动维护 DCC 中的人工/AI 分配比例。该过程周期长、规则难追溯，且容量变化时需要重复调整。

业务目标

  • 优先把高转化价值线索分给人工。
  • 人工满载时动态控制新增人工量，避免超接。
  • 人工不足时，充分利用人工承接能力。
  • 每次策略可解释、可审核、可回溯。

本版本边界

  • Agent 负责生成策略建议，发布前必须人工审核。
  • Agent分析和容量建议均使用上一完整业务日的数据（即 T+1：今天使用昨天已结算的数据），按日生成策略，不做实时重算。
  • 坐席达到最大接收量后，继续按现有逻辑挂靠主管，由主管二次分配。

2. 角色与权限

角色操作限制
运营查看 Agent 结果、调整建议、提交审核、导出策略无权绕过审核直接发布
项目/产品负责人审核规则、确认业务解释、批准发布或驳回需填写驳回原因
技术/数据维护数据访问、接口权限、DCC 导入接口和日志不替代业务审批
系统按活动版本执行匹配、记录策略版本和分派结果发布后版本快照不可修改

3. 核心流程

  1. 数据结算：等待数据源完成上一完整业务日结算，记录数据日期、来源、更新时间和是否完整。
  2. 生成草案：Agent 从约定数据源读取已结算数据、人工容量、继续跟进占用和当前规则，生成草案与解释。
  3. 规则校验：业务系统校验比例合计、适用范围和规则冲突；最低样本量由评分服务参考；有问题就不允许提交。
  4. 人工审核：Agent 原始建议只读；运营调整独立执行分配方案，审核人员按条通过并发布或驳回。
  5. 审核即发布：单条审核通过后立即调用 DCC 发布该规则；只有成功回执并返回规则 ID 才标记已发布，工作台同时记录发布版本。
  6. 执行与追踪：DCC 按已发布版本分配；每条新任务记录使用的策略版本，便于后续复盘和回滚。
时间口径：不固定承诺“每天几点自动生成”。触发条件应是“最新业务日数据已结算且完整”；若日报未完成，显示待数据状态，不生成不完整策略。

3.2 审核规则设置：人员与邮件通知分离

“开启审核通知”仅控制邮件发送；关闭时仍正常接收建议并支持查询、调整、审核、驳回及发布，审核权限不变。审核人员始终可配置；通知关闭只禁用邮件参数并保留原值。站内通知本期不上线，抄送邮箱不授予审核权限。

配置项处理规则生效边界
审核人员从账号人员多选、全选或清除；按权限服务授权执行审核发布。通知关闭仍可配置，不由邮件开关决定审核权限。
通知及抄送邮箱支持多个地址，以逗号、分号或换行分隔；开启通知时校验审核人及邮箱。保存后用于后续通知发送；发送失败留痕，不阻塞审核操作。
待审核通知频率实时针对新增有效待审；每小时/每日汇总全部有效待审，包含昨日和更早遗留。不受当前建议列表筛选或业务日期限制；通知关闭后停止发送。
超时提醒不提醒或1/2/4小时；首次成功通知起计，每条仍有效待审记录仅催办一次，跨日不重置。处理、失效、只读归档或通知关闭后不继续催办；发送前复核状态，避免重复提醒。

操作顺序：打开审核规则设置 → 配置审核人员及邮件参数 → 校验保存并记录操作 → 按频率发送有效待审通知 → 符合超时条件时催办。通知配置与执行来源配置、分派策略版本分别维护，任何通知配置变更均不发布或修改分派规则。

3.3 系统蓝图

下面按“谁提供数据、谁提供参数、谁提出建议、谁批准、谁真正执行”划分边界。Agent负责本次建议所需分析，业务系统负责审核、版本和发布。

① 数据来源

数据组：六类对象的七项率值、样本量及可追溯线索明细。

规则与运行数据：规则版本、坐席/排班和人工任务占用；容量数据也可由数据组提供或由 Agent 通过授权只读数据源查询。

只提供事实数据，不替业务决定比例。

② 业务系统

接收 Agent 返回结果，维护硬校验配置，负责结果接收和兜底校验。

校验低效、直派、比例、规则版本和权限；快照执行来源，去重复用或创建分配配置并逐条发布。

不要求冗余保存 Agent 的完整计算过程。

③ Agent建议

接收数据组批量/API或授权直连库表取得的线索明细和参数，整理分析并逐对象输出可建规则的 JSON 建议。

Agent可以返回相关对象；业务系统必须再次执行低效、直派和样本量兜底校验。

只生成草案，不修改线上配置。

④ 人工决策

运营核对 Agent 评分和比例；AI占比大于0%（含全 AI 100%）时，可选择“按比例”并补齐内部方案，或选择“不按比例”并补齐单一 AI 外呼类型。授权审核人员逐条审核，通过即提交 DCC 发布。

保留调整、驳回、发布及失败记录。

最终比例和AI执行方式由人工确认。

⑤ DCC执行

每条规则成功发布后形成一个新版本，该版本保存发布后的整套规则快照；新线索按当前生效规则分派。

任务记录命中规则ID和版本；下游效果按版本回看。

已分派任务不重派；失败保持旧规则。

数据与控制方向：数据组批量文件/API 或 Agent 授权直连库表 → Agent分析并返回JSON → 业务系统兜底校验 → 人工审核发布 → DCC执行 → 结果回到业务系统复盘。效果回传字段和接口仍需技术联调；没有回传时只能看分派结果，不能宣称已验证转化提升。

谁交给谁交付内容交付失败时怎么办
数据组 / Agent数据访问层数据组批量提供的，或 Agent 直连库表查询的线索明细、对象维度、事件指标、样本标识和数据日期；明细中保留直派标识。缺少必要字段或数据未结算时，不调用 Agent 生成建议，继续执行现行规则（仅作系统兜底）。
业务系统 / 数据访问层 → Agent规则数据源提供现行分派规则及版本；数据组批量/API或 Agent 授权查询提供排班/坐席容量、继续跟进任务占用和已分派人工任务。不能确认当前规则、数据批次或容量时，不让 Agent 用猜测值生成可发布建议。
数据访问层 → Agent数据访问层返回线索明细、数据日期、当前规则、容量数据和必要业务参数；不要求业务系统先计算分数。输入不完整时标记失败，不把部分结果当成完整策略。
Agent → 业务系统/运营默认模式返回对象评分和人工/AI总比例，完整模式另返回具体外呼类型及占全部线索比例；建议说明由业务系统生成。生成失败或漏掉应输出的对象时，保留旧版本并提示重新处理。
运营/负责人 → DCC经确认的最终执行分配及当前版本；等价启用分配比例配置复用，否则创建并关联，提交DCC时使用幂等请求。该条发布失败时不切换其有效规则，其他已成功发布规则保持有效。
DCC/下游 → 业务系统新任务命中的规则ID、策略版本及后续接通、到店、试驾、锁单结果。缺少下游效果时，只展示已分派数量与执行状态，明确标注效果数据缺失。

4.2 Agent分析所需指标与参数

Agent从数据组批量/API或授权只读库表取得已结算数据，并结合当前规则、容量、继续跟进占用和 AI 方案完成分析。目标值、权重、分配等级和映射由 Agent 维护；业务系统只保存请求、结果、校验和审核发布记录，不保存中间计算过程。

4.3 统计窗口与数据去重

统计窗口：以数据组上一完整业务日（T+1）结算结果为准；窗口参数由 Agent 配置维护，Agent 读取当前生效窗口。

统计范围：按数据组已结算口径统计，可包含直派线索；系统不对率值二次计算或扣除。

去重与追溯：沿用数据组口径；如需核验，按线索 ID、事件 ID和批次号追溯。

日期归属：Agent和容量均使用上一完整业务日（T+1）数据。

4.4 Agent分析闭环

A2A Agent负责目标值、权重、H/A/B/C分配等级、等级映射和人工/AI建议的完整分析闭环，并输出最终等级和比例建议。业务系统校验低效、直派、字段范围和比例合计，最低样本量仅供评分服务参考；每条建议在审核发布提交时再次校验最新有效状态。

5. 人工容量与日缺口

本版本按日生成策略，Agent分析和人工容量均读取上一完整业务日（T+1）已结算数据，不做实时重算。数据获取支持两种等价方式：由数据组按批次提供已结算数据，或由 Agent 通过受控只读连接直连库表查询。两种方式都必须带数据日期、批次/结算状态和字段版本；不允许查询未结算或实时变动数据。当天坐席达到最大接收量时，仍按现有逻辑挂靠主管，由主管二次分配。

指标建议定义使用场景

继续跟进占用今日仍有效且需要人工处理的延续任务数量；同一任务只计一次扣除已占用容量

5.1 低效对象配置与结果兜底校验

“低效对象”由运营在配置功能中维护，运营先选择六类规则中的一个已启用策略，系统自动带出该策略的规则 ID、匹配值、当前分派动作和版本；低效配置不再重复填写人工/AI比例或AI内部方案，直接引用关联策略。低效或直派对象不进入工作台评分和建议审核；最低样本量保留为评分服务参考参数，页面不据此自行拦截建议。Agent可以返回候选结果，但业务系统仍须校验低效、直派、字段完整性及规则适用范围。

配置/计算项产品定义作用
关联对象运营选择六类规则中一个“启用”状态的策略名称；系统保存策略 ID、版本、匹配值和当前分派动作，不允许手工输入对象值保证低效配置始终关联真实存在的普通分派策略，避免对象值填错或与现有规则脱节
命中判断按关联策略原有的完整匹配条件判断，不是仅凭策略名称或展示的对象值判断；一条策略若同时配置车系、门店或其他条件，须全部符合该策略原有条件避免把同一对象值下原本不符合该策略的线索错误纳入低效清单
低效判定条件线索命中已关联的低效策略后，直接继续执行该策略当前有效的人工/AI比例、AI外呼方式和版本；未命中的普通对象才按 Agent 建议进入审核，最低样本量由评分服务参考，不作为页面硬拦截门槛把业务已知的低效对象和 Agent 基于数据的建议分开，避免 Agent 擅自改变业务规则
分派设置来源人工/AI比例、AI内部方式、AI比例方案、规则状态和分派动作均从关联策略读取，低效配置不重复维护避免同一策略出现两套比例，保证普通策略调整后低效引用保持一致
容量不足时的调整只对未命中低效、直派的普通对象提出比例建议；按缺口生成建议，Agent分配等级高的对象优先保留人工；不采用固定5%/10%步长人工/AI总比例合计100%；AI占比大于0%时运营可选择按比例方案或不按比例的单一AI外呼类型
Agent职责读取明细和参数完成分析，输出评分与人工/AI总比例建议 JSON；不直接发布、不创建线上规则运营在策略建议与审核页补齐AI方式，逐条审核并提交发布

5.2 AI 分配默认方案与执行方案来源

工作台首个页签为“AI 分配默认方案”。默认使用“默认预设补齐”：Agent 提供人工/AI总比例，系统按执行AI占比匹配预设区间，内部比例只拆分AI份额。可维护多套预设并指定一套默认，按比例时区间覆盖1–100%、连续无重叠，每区间内部合计100%；不按比例时将AI份额分给单一AI类型。

另一模式为“Agent 完整方案”，直接采用Agent返回的具体外呼类型及占全部线索的比例，不自动读取默认预设。明细缺失、类型非法、重复或比例校验失败时标记待补齐，允许人工修正但不得直接发布，不静默回退预设。全人工无需AI明细。

切换防误操作：选择模式仅形成未保存状态，当前生效模式仍用于接收新建议；点击“保存并生效”并确认后才切换，取消不生效。保存仅影响此后新接收建议，已有建议及已发布策略保留来源与快照。Agent模式页头不展示新增方案；展开维护备用预设后，才在预设区域显示新增预设。

执行方案调整：Agent原始建议只读。运营在本条执行方案修改人工占比（0–100整数），AI自动取余；再选择AI单一类型或内部拆分。人工100%隐藏AI区域，无需预设；AI100%两种方式仍可选。预设支持按名称、编号、AI类型搜索；调整只影响本条，不回写公共预设。默认模式可主动读取最新预设，Agent模式恢复时只还原Agent原始完整方案。

原始建议：人工60%／AI40% → AI内部一知20%／科大讯飞80% → 最终：人工60%＋一知8%＋科大讯飞32%。若执行人工改50%，AI变50%，最终为人工50%＋一知10%＋科大讯飞40%；原始建议仍为60%／40%。

5.3 分配比例配置自动创建与复用

审核发布时以最终执行分配的依据、条件、外呼类型、比例及推送配置等内容做规范化去重，存在完全等价且启用的配置直接复用，否则创建并关联到发布规则。打开或保存调整弹窗不创建配置。并发及重试使用幂等控制，防止重复创建或发布；DCC失败不能将配置关联误标为生效，须核实回执后重试并明确失败补偿处理。

配置列表显示“人工创建／策略审核自动创建／回滚自动创建”等来源，支持按来源及批次、对象检索；详情保留创建人、时间、来源批次、对象和规则。复用已有配置保留原创建来源，新引用另留痕。预设是生成执行分配的模板，分配比例配置是最终规则所引用的实体，两者分别维护。

5.4 名单导入导出与建议导出

低效对象配置和直派名单统一提供“导入数据”“导出数据”。导入沿用上传、预览确认、完成三步，支持模板、逐行错误、失败明细下载和部分成功；重复行跳过不覆盖。低效导入确认时复核维度及关联规则仍启用；直派仅大项目名。策略建议与审核支持“导出数据”，导出当前批次及筛选命中的全部分页条目，包含接收时间、原始建议、执行方案、来源及审核记录。

策略建议列表按规则 ID 读取当前启用规则的匹配值，并按关联的比例配置 ID 展示“模板规则”内容。例如渠道 R2 的 CH-002 关联 AP-003，当前规则模板显示“科大讯飞-冷线索70%，人工外呼30%”；生产样本量、评分及建议比例来自数据服务和Agent接口；原型示例不代表真实计算结果。

遗留待审核建议跨日继续可审。数据结算且成功产生同一对象的新建议后，旧的未发布建议保留并标记“已失效”，禁止审核、修改和发布；失败批次不替代旧建议。审核和发布提交时复核最新有效版本。已发布策略持续生效至新版本正式发布；建议记录按业务日期满六个自然月只读归档，生产环境需持久化与归档接口支持。

业务系统兜底校验：Agent 返回结果后，业务系统检查规则维度和对象值是否属于允许范围、是否命中低效关联或直派名单、人工/AI 比例是否合计 100%、规则名称是否完整。审核发布时再次校验建议为最新有效记录；按最终执行方案校验人工及AI总比例、具体类型和内部拆分。最低样本量是评分服务参考参数，不作为页面自行拦截建议的硬门槛。校验失败的规则不得发布，原有效规则继续执行，并记录失败原因。

7. 策略结构与生命周期

DCC 维护六类相互独立的分配规则：专营店、车系、SmartCode、SC大项目名、线索状态、渠道。低效配置从对应维度中选择一个“启用”的普通策略名称，保存该策略的规则ID和版本作为关联依据；低效命中后直接引用这条策略的人工/AI比例、AI内部方式、分派动作和版本，不再维护第二套设置。每条普通规则包含规则维度、匹配值、路由优先级、人工/AI总比例、AI内部方式及版本信息。六类规则不拼接成组合条件，系统按“专营店 → 车系 → SC → SC大项目名 → 线索状态 → 渠道”的顺序匹配，命中第一条有效规则后执行。

状态含义允许操作
待补齐执行明细缺失或不合法，不影响线上人工补齐、校验；不得发布
待审核建议已接收，等待授权人员核对，缺失执行明细时需补齐后才能发布通过、驳回
发布中单条审核已通过，正等待 DCC 发布回执等待结果、查看异常
生效DCC 已成功发布并可执行查看、停用、回滚到上一版本
发布失败/已驳回DCC 未确认发布成功或业务审核驳回查看原因；发布失败可校验后重试，驳回可修改后重审

建议按条审核；每条审核通过即提交 DCC 发布，成功后记录 DCC 返回的正式规则 ID及版本号，并建立独立发布版本和发布后的整套规则快照。同一建议批次可能产生多个正式版本；版本查询须支持按建议批次、规则维度、匹配值、状态及版本号或 DCC 规则 ID 定位，维度与匹配值以该版本本次变更的同一条规则为准，结果服务端分页。批量审核逐条处理和留痕，失败条目不得标记已发布，原有规则继续生效。业务系统记录建议批次与条目 ID、正式规则 ID/版本、逐条正式规则快照、每条规则的审核人和审核时间、接口结果、发布操作人和前后版本关系；Agent 保留完整建议计算详情，业务系统不重复保存整份计算明细。
