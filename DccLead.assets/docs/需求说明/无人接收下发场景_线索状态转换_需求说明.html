v3.0 · 业务规则已确认 · 原型与规格

预评分驱动的线索状态转换

当回访结果为「无人接听下发」且有效评分命中已配置区间时，采用该区间的五项执行值更新线索和回访字段，并按原流程同步主机厂。

适用：手动回访、人工批量、AI 批量、预外呼自动下发本文交付：确认版业务规则及研发补充说明
DCC 负责结果转换与同步，主机厂负责根据接收到的状态执行拦截。本文未表示正式接口已接通，也未表示主机厂拦截效果已经联调验证。

1. 目标与范围

统一人工、AI 与自动下发场景对低分「无人接听下发」记录的处理口径。坐席手动填写时明确提示原因，并在覆盖其填写内容前由坐席确认；后台批量逐条处理，不阻断其余记录。

场景处理入口命中后的动作
员工单条手动操作培育任务中选择客户，在原有三栏工作台直接填写回访工单；拨号沿用现有外呼工具栏工单加载时查询预评分；选择时提示；提交时由坐席选择返回修改或按规则转换并提交
人工批量、AI 批量批量任务逐条执行、实际同步前后台自动转换字段，继续既有同步流程
预外呼及其他自动下发自动任务产生待处理回访结果、实际同步前复用统一判定与字段映射，不增加逐条确认弹窗

默认入口以本次有效的回访结果为条件，不因一次通话无人接听就直接触发；通话状态配置中明确选择引用统一判断的场景，按已确认方案 A 执行独立入口条件，见第 3 节。不新增“禁止分配给坐席”规则，也不把转换记录从主机厂同步流程中剔除。已完成下发的记录，后续才出低分不补改、不重新同步。

3. 统一判定与评分读取

命中条件：已配置有效低分区间 ＋ 本次回访结果为「无人接听下发」＋ 已取得有效评分 ＋ 评分落入低分区间。以上四项适用于原有入口。AI 外呼的通话状态配置选择「是否优先执行预评分转换规则＝是」时，采用下述方案 A 入口条件。

本次情况处理结果
未配置低分区间跳过本规则，沿用原流程及既有表单校验
回访结果为其他值跳过本规则，不修改相关字段
无评分／评分未完成／评分查询超时或异常／评分数据无效按无可用评分处理，沿用原流程；记录原因，不把异常当作低分
有效评分未落入区间本规则通过，沿用原流程
有效评分落入区间单条手动提交进入确认分支；批量及自动任务直接转换

单条手动操作的两次读取分别发生在工单展示时与提交时，均使用当前客户及有效任务所关联的初评结果。选择回访结果时使用打开工单时取得的结果进行判断，不触发重复查询或重新初评。第 8 分钟才出的评分，可以用于第 20 分钟的新操作；第 3 分钟已完成下发的记录不因第 8 分钟出分而追溯转换。

通话状态配置引用：方案 A

适用页面为「AI外呼配置 → 通话状态配置」。命中条件增加渠道编码多选，非必填，未选择表示不限渠道，选择多个时命中任一渠道即可；复用渠道编码线索分配策略的选项与搜索、全选、清空交互。渠道与外呼类型、通话状态共同匹配，原通话状态内部且／或逻辑不变。

增加「是否优先执行预评分转换规则」，单选是／否，默认否，兼容原配置。选择否时执行原动作；选择是且本配置条件命中后，直接判断共用低分区间，不额外要求回访结果＝无人接听下发。分数命中任一区间时执行该区间的五字段转换，原动作不再执行；未命中、无分、读取失败或未配置区间时执行原配置动作。原动作保留编辑并明确标为兜底使用，不因选择是而清空。

本例外只适用于明确选择是且已命中的通话状态配置，不将其他入口的回访结果前提移除。原型覆盖字段维护、详情列表回显与判定模型；真实话单事件、权限与服务写入仍待联调，不能把模拟模型当作服务已接入。

评分展示口径：上方沟通提示与右侧智能预评标注“当前预评分”，共用打开当前回访工单时的实时查询结果；线索详情标注“初始预评分”，保留任务创建时的评分快照，并通过 ⓘ 悬停说明“任务创建时保存的评分”。例如初始 82 分、当前 20 分可同时存在，快照不随当前查询更新。不增加时间、对比行或常驻说明条。回访表单不重复显示评分；命中规则时在原因提示及提交确认中说明所用分数、区间与处理原因。提交复核取得更新评分后，当前评分同步更新；查询中或无分时展示对应状态，不用快照冒充当前结果。

研发核对：初评结果与线索／任务的关联键、评分有效性标记、评分范围和精度、查询响应时限由接口契约明确。数字 0 若是合法评分，必须作为有效分值参与判断，不能被当作无分。

“三天四次无法接通”为用户指定的转换映射，不代表系统已经核验真实发生了三天四次未接通。处理记录中另注明“低分规则转换”，用于区分触发原因。

5. 手动回访工单：两次校验

5.1 打开工单时查询，选择结果时判断

  1. 坐席在「培育任务」中选择客户，原有三栏工作台的中间区域展示回访填写表单，拨号沿用现有外呼工具栏。工单加载时，按当前客户与当前有效任务查询一次预评分；未配置低分区间时仍可读取实时评分供沟通提示及智能预评展示，本次转换规则不执行。
  2. 查询异步进行，填写与拨号均可正常使用。仅查到低分时不立即弹窗、不修改字段，因为坐席尚未选择本次回访结果。
  3. 坐席选择「无人接听下发」时，使用本次打开工单取得的评分进行规则判断，不再额外查询。未命中、无分或仍在查询时，正常填写、不等待；提交时仍由后台读取最新评分校验。
  4. 选择「无人接听下发」并命中低分时，展示提示，保留坐席已填写的全部内容，不自动覆盖。坐席可以改选其他回访结果；如果仍保留该选项并提交，则进入第二次校验。
  5. 若查询稍后返回，只有工单仍打开、客户与任务未变化、尚未提交且当前仍选择「无人接听下发」时，才根据结果提示。坐席已改选其他结果时不弹过期提示，不覆盖新的选择。
  6. 关闭工单、切换客户或切换任务时，使原请求失效；新打开的工单重新查询，不复用其他客户或任务的分数。反复切换回访结果不重复请求评分，也不因后来出分追溯修改已提交记录。
提示文案：该线索评分为 XX 分，命中低分区间，不能直接按“无人接听下发”提交，请修改回访结果。

首次命中弹出原因提示，坐席关闭提示后恢复原表单，保留「无人接听下发」及全部填写内容；可改选其他结果，也可保留当前选项后提交，进入第二次校验。该弹窗不提供直接自动覆盖入口。XX 及低分区间显示真实返回值，不在这一阶段自动保存、同步或改变持久化状态。

6. 批量与系统自动处理

业务状态与同步状态分开保存：转换后的线索状态采用命中区间的配置值，后续同步请求提交不得再把它覆盖为「已下发」。原创建快照、首次状态与历史记录保持不变。状态转换记录按任务编码与线索编码关联，记录原值、最终值、当次评分及区间、判定原因、保存结果及同步状态；人工单条仅在保存成功或实际保存失败时写入记录，选择提示、取消或返回修改不生成已处理记录；无评分或读取失败明确记录放行原因。

  1. 沿用既有条件创建操作或批次，不弹出逐条低分确认窗口。
  2. 逐条在实际同步前，使用该条本次有效回访结果、当前可用评分及统一配置判定。
  3. 命中：后台按第 4 节转换五项字段，持久化成功后继续既有主机厂同步流程。
  4. 未命中或无评分：继续原有保存和同步流程。
  5. 单条数据处理失败：单独记录并按既有失败机制处理，不因该条失败让其他可处理记录全部失败。

结果统计建议区分：已保存／待同步、已同步、其中规则转换数量、处理失败数量。规则转换数量是业务处理标记，不能作为“拦截剔除数量”或与正常同步数量重复相加。DCC 接口成功也不等同于已验证主机厂实际拦截。

人工批量、AI 批量与自动下发共用同一判定能力；自动场景先通过原入口的有效任务、SmartCode、触发条件及下发资格校验，再进入本规则，不能用通话状态或 AI 标签代替「回访结果＝无人接听下发」。本规则不绕过既有有效任务、重复下发、权限和其他业务限制。

7. 统一低分区间配置

已确认：人工、AI、自动下发共用一套配置，可新增、删除多个分数区间；每个区间分别配置线索状态、回访结果、异常原因、回访描述和意向级别。默认不预设分值，未配置时不执行转换。分数区间均包含上下限；区间之间不得重叠，端点相同也算交集，例如 0–30 与 30–60 不允许，0–30 与 31–60 允许。有效评分至多命中一个区间，使用该区间的五项执行值；无分、读取失败或区间外沿用原流程。统一保存前校验全部区间及动作并二次确认，对照已保存值与新值；操作人须勾选已核对各区间的线索状态、异常原因和意向级别才可确认。返回修改、关闭或 Escape 保留草稿而不保存；配置版本变化时拒绝覆盖。删除全部区间并确认保存后停止转换，仅对后续操作生效，不补改历史记录。

一致性单次判定固定使用同一配置版本及命中区间的五项处理值；确认框、最终保存和转换记录采用相同值。确认期间配置变更不改变已展示的覆盖内容，新操作使用新配置原型已实现配置快照
权限与隔离管理员编辑、坐席按规则操作；遵守现有组织及数据权限，不因“共用一套”打通不同租户配置沿用现有权限体系，权限点待映射
版本与审计记录保存人、时间、配置版本及前后值；每次业务判定记录采用的版本研发实现要求

厂商回流同步在同步前兜底：本次操作已完成转换的线索沿用已保存结果，不重复查分或覆盖；其余仅在回访结果为「无人接听下发」时查询预评分。命中后按本次统一配置更新DCC五项字段，保存成功后再同步厂商；保存失败不发送，同步失败保留DCC已保存结果。转换标记按本次操作和线索关联，不永久跳过后续独立操作。

全局接入约定：各保存／同步入口使用同一判定与同一配置，不按六类来源分别启停或复制分数区间。接入场景表只展示覆盖情况，不能通过勾选来源限制规则。另列 AI通话状态处理场景：通话状态配置选择优先转换且本配置命中后，直接判断共享低分区间，不要求回访结果；未转换仍执行原动作。记录的操作来源增加「AI通话状态处理」，与人工批量下发、AI批量下发、人工预览外呼、人工预测外呼及厂商回流同步共同组成六类来源。仅执行判定预览不产生已保存记录，引用规则的模拟执行在保存后记录处理结果，失败保留处理前字段。新增入口须确认有效回访结果、真实来源及服务执行时点后接入。天网付费自动下发是批量下发的自动触发方式，按实际执行链路归入人工批量下发或 AI 批量下发，不另列独立来源或待核对入口；正式服务接入仍需验证自动触发与手动提交共用批量处理链路。其他新增路径按实际执行链路核对接入。后台生成优先顺序为原配置匹配 → 候选字段 → 统一低分转换 → 最终保存 → 既有同步；原配置不得在之后回写覆盖已转换字段。

现有分配策略中的预评分区间用于分配比例，不能自动认定其最低档就是本需求的低分区间，也不直接修改那些策略。

8. 保存、主机厂同步与处理记录

闭环顺序：判定／取得坐席确认 → 保存最终字段 → 按既有流程同步主机厂 → 回显保存与同步结果。确认窗口出现时尚未执行本次持久化与同步。

8.1 失败与重复操作

异常处理要求

重复提交、重复确认、网络重试按本次有效操作防重，避免重复回访记录、重复处理任务及重复下发
表单或任务已被其他操作更新服务端校验版本与当前任务有效性，提示刷新核对；不以旧表单覆盖新状态

8.2 数据记录与工程建议

记录线索与任务标识、本次回访记录、操作来源、人工／系统处理方式、原填写值、最终值、评分与评分来源标识、查询时间、规则配置版本及命中结果。评分读取与查询接口应明确“不重新发起评分计算”。

保存最终五项字段应作为一次一致的业务处理，避免部分字段成功、部分失败。保存与待同步任务需具有一致性保障。服务端保留规则校验权，不能依赖前端置灰或提交的“已通过”标记。

以上属于让已确认业务规则可可靠落地的工程补充，不表示已确定数据库结构、API 路径、消息队列或外部接口能力。沿用现有实现完成即可，不扩大一期基础设施范围。

当前单条回访原型的演示方式

  1. 在「培育策略 → 预评分转换规则」配置一组或多组分数区间，例如 0–30 分与 31–60 分，每组分别填写五项执行值；保存后对后续操作生效。默认留空，删除全部并保存后不转换；区间包含上下限，不能交集。
  2. 打开「培育任务 → 我的任务」，选择普通培育客户，在原有三栏工作台中填写回访工单，拨号沿用原外呼工具栏。
  3. 底部「原型演示设置」仅切换评分／保存模拟场景，例如低分 20、无分、打开无分提交时出低分或保存失败；不再编辑低分区间。
  4. 选择「无人接听下发」命中时提示原因，保留全部输入；关闭后仍保留原选择。可改选其他结果，或保留原选择并提交，再进入评分复核及五字段覆盖确认。
  5. 返回修改不保存、不生成已处理记录；确认后模拟保存，并在状态转换记录中显示本次入口、配置版本、原值及最终值。保存失败保留原填写内容，只记录失败尝试。

9.2 批量与自动场景演示

  1. 在统一配置页先设置区间，再打开「线索管理 → 线索分发审核」，进入人工线索分发或 AI线索分发页签，沿用原有勾选和确认下发入口。
  2. 展开底部「原型演示设置」并载入混合样例；这只重置演示记录和模拟评分，不更改统一低分区间。样例包含低分、高分、无分及其他回访结果。
  3. 勾选后按现有流程确认；同步前逐条判断，命中项更新五字段，其余正常流转，单条保存失败不影响其他记录。后续同步状态不能覆盖命中区间配置的业务状态。
  4. 从「统计报表 → 预评分转换记录」独立菜单查询，按六类来源、处理结果、任务编号或线索编号筛选（编号输入不匹配批次号）；下发批次仅在批量来源的展开明细展示，从原下发日志按批次定位的入口保留，展开查看具体入口、配置版本、关联话单／工单以及字段前后值。原下发日志只负责批次与同步信息，并保留按批次查看转换记录的链接。预评分转换记录页不再提供查看下发日志按钮，维持独立浏览。页面内置 24 条 DEMO 编号测试记录，覆盖六类来源及已转换、未命中、无分、处理失败四种结果，支持筛选、分页及展开字段对照。演示记录使用独立配置快照，与实际操作审计分开保存，不修改统一规则或业务数据，不代表真实执行或同步成功。
  5. 人工来源采用任务入口信息，不从坐席当前登录的工具模式猜测。原型中的主动选客工单默认标为人工预览外呼；预测话单生成链路明确标为人工预测外呼，正式来源字段由任务／外呼服务提供。

9.3 预测话单生成链路

  1. 在「人工外呼配置 → 回访工单配置」底部展开「话单生成与全局转换演示」。可选现有已启用配置或标注为独立示例的无人接听下发配置；独立示例不修改原配置。
  2. 演示按选中配置提供状态、渠道、媒体和初始状态样例。时长和返回次数条件需填写实际演示值，缺少数据时不匹配。按权重从小到大选择首条命中配置；停用项不参与。
  3. 先由配置生成候选回访结果、描述、级别及计划，再使用同一实时评分和统一区间判断。配置生成下次回访时不转换，不能仅以原话单无人接听触发。
  4. 命中后更新五项字段，计划与指派规则仍保留；先保存最终值，再进入既有流转。页面回显原配置值及最终值，统一记录关联话单与生成配置；不实际指派坐席或调用主机厂。
  5. 同一线索的同一话单已成功生成时不重复生成，也不因稍后改配置或出分补改旧结果。失败不生成有效工单，可以重试，并保留失败尝试记录。
当前实现统一规则配置页、人工单条／人工批量／AI 批量模拟及预测话单生成工单的完整模拟链路，数据与配置仅在原型会话内保存。正式权限控制、持久化、外呼事件触发、主机厂接口及回执失败处理尚待实现与联调。日志中的同步请求已提交（模拟）不表示已收到主机厂回执或验证其拦截结果。
