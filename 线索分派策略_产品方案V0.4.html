线索分派策略｜产品方案 V0.4

面向 DCC 培育平台的 Agent 智能生成分派策略方案（评审稿）

当前阶段：方案评审前策略生成：Agent 草案最终生效：人工确认发布更新时间：2026-10-04
一句话结论：系统根据已结算数据和运营配置完成评分、容量与比例校验，Agent 读取这些计算结果生成“可解释的策略草案”；运营/项目负责人审核、修订并发布，DCC 按已发布版本执行。Agent 不自行定义低效规则、不修改参数，也不绕过人工审核直接发布。

1. 背景与目标

现状是人工定期查看《NEV 总部培育渠道核心日报》，清洗“人工”场景后计算效果、排名，再手动维护 DCC 中的人工/AI 分配比例。该过程周期长、规则难追溯，且容量变化时需要重复调整。

业务目标

  • 优先把高转化价值线索分给人工。
  • 人工满载时动态控制新增人工量，避免超接。
  • 人工不足时，充分利用人工承接能力。
  • 每次策略可解释、可审核、可回溯。

本版本边界

  • Agent 负责生成策略建议，发布前必须人工审核。
  • 本版本覆盖日级策略、实时容量控制、DCC 发布、版本审计和效果追踪。
  • 外部接口未具备时，使用明确的降级模式，但目标能力仍纳入本版本交付。

2. 角色与权限

角色操作限制
运营查看输入数据、生成草案、调整参数、提交审核、导出策略无权绕过审核直接发布
项目/产品负责人审核规则、确认业务解释、批准发布或驳回需填写驳回原因
技术/数据维护数据接入、计算服务、DCC 导入接口和日志不替代业务审批
系统按活动版本执行匹配、记录策略版本和分派结果发布后版本快照不可修改

3. 核心流程

  1. 数据结算：等待最近业务日的 D智投日报完成，标记数据日期、来源、更新时间和完整性。
  2. 生成草案：Agent 读取已结算数据、人工容量计划、延续任务占用和当前生效策略，生成草案与解释。
  3. 规则校验：系统校验总比例、适用范围、阈值、样本不足和冲突规则；失败则阻止提交。
  4. 人工审核：运营可调整建议，负责人审核通过或驳回。
  5. 导入/发布：生成 DCC 导入文件或调用待确认接口；以“导入成功”和“发布成功”分别记录。
  6. 执行与追踪：DCC 按活动版本分配；每条新任务记录策略版本快照，便于后续效果分析和回滚。
时间口径：不固定承诺“每天几点自动生成”。触发条件应是“最新业务日数据已结算且完整”；若日报未完成，显示待数据状态，不生成不完整策略。

4. 数据与评分

4.1 输入数据

数据用途当前状态
人工场景线索量判断供给规模、缺口和样本是否足够日报已有，需确认唯一键及结算时间
接通、有效、试驾、锁单计算渠道/项目历史效果分来源可见，公式与统计窗口待确认
人工容量计算计划承接上限及动态剩余量原型有“当日任务最大接收量/新任务最小接收量”，接口未证实
继续跟进任务占用人工容量，避免新任务超接按有效“下次回访”工单计数；是否只计今日到期待确认
当前生效策略避免重复覆盖，形成版本差异需提供策略 ID/版本快照查询接口

4.2 四项效果分（建议口径，待业务确认数值）

原始资料中的四项指标需要先计算转化率，再换算成 0–100 分。推荐按销售漏斗逐层计算，使每一项都能解释具体问题：

指标推荐公式它回答什么问题
接通率接通线索数 ÷ 应拨线索数线索是否能够被有效联系
有效率有效线索数 ÷ 接通线索数接通后有多少线索具备有效意向
试驾率完成试驾线索数 ÷ 有效线索数有效线索转化为试驾的能力
锁单率锁单线索数 ÷ 完成试驾线索数试驾后最终成交的能力

转化率建议按目标值换算为得分，避免直接把百分比相加：

指标得分 = MIN(实际转化率 ÷ 目标转化率 × 100, 100)

例如接通率为 60%、目标接通率为 75%，则接通得分为 80 分。目标值可以按全国、区域或渠道配置，但必须由业务确认，Agent 不得自行生成。

4.3 统计窗口与数据去重

统计窗口：建议使用最近 30 个已结算业务日，不使用当天尚未结算的数据。7 日窗口反应快但波动大，14 日可作为过渡；正式默认建议采用 30 个已结算业务日。

统计主体：按线索唯一 ID 去重，不按通话次数、工单次数或重复导入次数计数。同一线索在同一窗口内至少接通一次即计为 1 条接通线索；至少完成一次有效试驾即计为 1 条试驾线索；锁单也按唯一线索计 1 条。

已确认口径：以线索首次进线日期作为统计归属，后续接通、试驾、锁单结果回填到该线索所属的进线统计窗口；同一统计窗口内按线索唯一 ID 去重。无唯一 ID、节假日和异常日的处理由数据服务按已确认数据质量规则标记，异常数据不得进入正式策略。

4.4 综合分与权重

综合效果分 = 接通得分 × W1 + 有效得分 × W2 + 试驾得分 × W3 + 锁单得分 × W4

W1–W4 表示四项指标在综合效果分中的占比，必须满足 W1 + W2 + W3 + W4 = 100%。权重越高，该指标对排名、人工优先级和 AI/人工比例建议的影响越大。

本版本建议由业务维护固定权重，Agent 只读取并计算，不自行调整。权重变化必须生成新的参数版本和策略版本；系统运行积累效果数据后，再通过实验调整。

4.5 分配等级

历史资料中的 H/A/B/C 仅作为当前业务规则草案：H≥70、A=60–70、B=50–60 倾向人工，C<50 倾向 AI；阈值和边界是否可配置、评分是项目级还是线索级，需业务确认。

5. 人工容量与日缺口

必须区分“计划口径”和“实时口径”，避免用当天累计进线量直接覆盖当天上限。

指标建议定义使用场景
计划人工上限排班计划与坐席“当日任务最大接收量”汇总；是否包含继续跟进由业务确认Agent 生成日策略
继续跟进占用今日仍有效且需要人工处理的延续任务数量；同一任务只计一次扣除已占用容量
新增人工已分配当天已按人工策略成功分派的新任务数量实时剩余容量
实时剩余容量计划人工上限 − 继续跟进占用 − 新增人工已分配每次新线索分派前判断
待分派人工候选符合人工策略、尚未成功分派且未失效的线索计算实时缺口
实时缺口待分派人工候选数量 − 实时剩余容量，最低按 0 处理决定是否降级 AI/进入待分派
本版本交付要求：DCC 应提供“已分派数量、延续任务占用、分派结果”等接口，以支持实时剩余容量控制。若接口在评审时尚未具备，系统保留日级建议和偏差提示作为降级模式，并明确接口补齐、联调和验收责任；实时能力仍属于本版本目标。

5.1 低效对象配置与动态调配

“低效对象”不应由 Agent 自行猜测，也不应在方案中写死为某一种维度。由运营在策略配置中选择评估对象类型（如项目、渠道、SmartCode、车系或其他已确认评分对象），并维护效果指标、低效阈值、最低样本量、最低人工比例和最高 AI 比例。评估对象范围须先与评分对象口径一致；配置型样本量等数量阈值使用正整数输入并由服务端校验。

配置/计算项产品定义作用
评估对象类型运营选择项目、渠道、SmartCode、车系等对象；具体范围受评分对象结论约束决定系统按什么粒度识别高效/低效
低效判定条件配置效果指标、阈值和最低样本量；仅当样本量达标且指标低于阈值时标记为低效避免用小样本或未经确认的口径降低人工比例
比例边界配置默认人工比例、人工最低比例和 AI 最高比例约束 Agent 建议和系统自动调整范围
容量不足时的调整先保持高效对象人工比例，再按低效程度从低到高增加 AI 比例；人工缺口转化为比例变化时不得突破配置边界在不超过人工承接能力的前提下，优先把人工资源留给高效对象
Agent职责读取运营配置、计算缺口并生成变更前后建议；不能自行新增评估对象、修改阈值或直接发布保证建议可解释、可审核、可追溯

以上是新增的配置和建议能力，不代表 Agent 可以直接修改正在生效的比例。建议经运营确认、审核和发布后才形成新策略版本；单条线索分派时仍须实时检查人工剩余容量。默认比例、上下限具体数值，以及“缺口→比例变化”的计算公式，仍由业务与运营确认。

默认落地算法：每日生成一份策略草案；系统先按“计划人工上限 − 继续跟进占用 − 当日已分派新任务”计算剩余人工容量，再把人工容量优先分给高效对象，低效对象按运营配置的低效程度从低到高分配。人工比例只能在运营配置的最低人工比例和最高 AI 比例内变化。剩余无法由人工承接的线索默认进入 AI；若 AI 也达到系统容量上限，则进入待分派队列并告警。实时分派只做容量保护，不直接修改已发布策略。

6. Agent 如何生成策略

步骤Agent 处理系统约束/输出
① 数据检查检查日期、来源、缺失、重复和样本量输出数据质量状态；不完整则不生成正式草案
② 效果计算读取系统已计算的四项转化率、目标值、统计窗口、去重口径和综合分评分服务保存公式版本、目标值、窗口、去重口径和权重；Agent 不重复计算或改写结果
③ 样本处理按待确认的评分对象检查日新增线索量；少于3条时标记“样本不足”不生成可用于本次排名的有效评分，也不据此调整分配比例。相关线索仍按当前已生效的路由规则分派；是否展示原始指标值待业务确认
④ 容量计算读取系统按计划上限、延续任务占用和已分派新任务计算出的剩余容量与缺口容量服务产出明细，0 可作为计算结果；Agent 不自行修改容量字段
⑤ 生成建议按运营配置识别低效对象；高效对象优先保留人工，低效对象按低效程度从低到高增加 AI 比例每条建议说明“配置依据、变化、容量影响”；不突破比例边界
⑥ 生成策略行按六类独立规则维度生成分配建议，并写入匹配值、优先级和分配比例六类规则不组合判断；命中更高优先级的有效规则后停止继续匹配

建议输出至少包含：策略名称、数据日期、策略范围、综合分、四项分值、权重、样本量、人工比例、AI 比例、容量/缺口、变更前后对比、解释、风险、置信状态。样本不足的对象单独显示状态，不输出用于本次排名或比例调整的有效评分。

6.1 Agent 执行与输出定义

Agent 不直接凭空生成规则，而是读取已结算数据和已确认参数，生成结构化的“策略草案”。推荐执行链路如下：

数据结算完成 → 读取输入 → 计算评分 → 判断样本 → 计算容量/缺口 → 生成策略建议 → 系统校验 → 人工审核 → DCC 导入/发布

Agent 输入数据

输入类别具体内容用途
效果数据接通、有效、试驾、锁单及其统计窗口计算四项效果分和综合分
线索数据项目、渠道、SmartCode、门店、线索状态、线索量确定策略适用范围；评分对象是否按各维度分别计算需业务确认
容量数据坐席最大接收量、新任务最小接收量、排班状态计算人工可承接量
继续跟进数据有效且未结案的“下次回访”任务扣除已占用人工容量
当前策略当前策略 ID、版本、匹配条件、人工/AI 比例生成变更对比，避免覆盖有效策略
业务参数四项权重、目标值、样本不足阈值、保客和低效规则约束 Agent 的计算和建议边界

Agent 结构化输出

输出区块必须包含的字段说明
策略基本信息策略名称、数据日期、统计窗口、生成时间、草案版本、生成状态说明本次建议使用了哪批数据和哪一版参数
策略建议行规则维度、匹配值、路由优先级、四项分、综合分、样本量、人工比例、AI 比例形成可校验、可导入 DCC 的独立规则记录，不拼接六维组合条件
容量明细人工计划上限、继续跟进占用、新任务已分派、实时剩余容量、日缺口解释比例为什么发生变化
变更说明变更前后比例、调整原因、预期影响帮助运营和负责人审核
风险与状态数据缺失、样本不足、接口不可用、校验结果、风险提示不确定时必须显式提示，不得伪装成正式结果
示例解释：Agent 针对“大项目名=项目A”生成一条人工 70%、AI 30% 的规则建议；同时针对“渠道编码=渠道001”生成一条人工 40%、AI 60% 的规则建议。若同一线索同时命中两条规则，系统按固定优先级执行命中更靠前的有效规则。输出中必须说明规则维度、匹配值、优先级、评分依据、容量计算和变更影响。

Agent、系统、人工和 DCC 的职责边界

参与方负责内容禁止事项
Agent读取系统计算结果和运营配置，生成结构化建议、解释和风险提示不得自行计算或改写指标、权重、阈值、评分对象、比例边界，也不得绕过审核发布
系统规则校验、版本保存、差异对比、导入发布、日志记录校验失败时不得显示为已生效
运营/负责人审核、调整、批准或驳回策略不得直接覆盖已生效历史版本
DCC按已发布版本执行线索分派并返回执行结果接口失败时不得重复创建或重复分派

Agent 输出验收标准

  • 同一份输入数据和同一版本参数，重复生成结果一致。
  • 每条建议都能追溯到数据日期、公式、权重、容量和规则来源。
  • 输出必须包含结构化策略行，不能只有自然语言说明。
  • 数据不完整、比例不闭合、范围冲突时，系统阻止提交正式策略。
  • Agent 不能绕过人工审核直接发布。
  • 发布后每条线索都记录策略 ID 和版本号。
  • 生成、校验、导入、发布任一环节失败，都有明确状态和错误提示。

6.2 Agent 提示词与实现交付物

产品不应只提交一段自然语言提示词，而应提交一份“Agent 执行契约”。最终实现至少包括：提示词版本、输入数据 Schema、结构化输出 Schema、工具/接口权限、系统校验规则、人工审核节点和验收案例。提示词负责约束 Agent 的判断和表达；公式、容量、比例边界、权限和发布动作必须由系统代码控制。

交付物产品需要定义的内容开发实现要求
Agent 角色与任务读取已结算数据和已确认参数，生成待审核策略草案及解释固定为单一职责 Agent；运行时动态传入当前策略、容量和配置
输入 Schema评分结果、样本量、运营配置、容量/缺口、当前策略版本、数据质量状态字段类型、单位、必填性、枚举值和缺失处理由接口约束
输出 Schema策略行、调整前后比例、依据、容量影响、风险、状态、不可生成原因使用结构化 JSON；缺失或非法字段不得进入发布流程
不可执行边界不得改权重、阈值、评分对象、比例上下限，不得直接发布或回滚用服务端权限、校验和审批流强制限制，不能只依赖提示词
验收案例正常容量、容量不足、样本不足、数据缺失、比例超限、六类规则命中冲突保留输入、输出、校验结果和人工处理记录，用于回归评测
仅保留三类参数确认：低效对象的具体配置值（对象、指标、阈值和最低样本量）、人工比例上下限及调整步长/公式、Agent 的具体触发时间。其他执行边界按本方案默认口径实现：系统计算和校验，Agent 输出草案，人工审核发布，实时分派不改写已发布版本。

7. 策略结构与生命周期

DCC 维护六类相互独立的分配规则：专营店、车系、SmartCode、SC大项目名、线索状态、渠道。每条规则包含“规则维度、匹配值、路由优先级、人工/AI分配比例”及版本信息。六类规则不拼接成组合条件，系统按“专营店 → 车系 → SC → SC大项目名 → 线索状态 → 渠道”的顺序匹配，命中第一条有效规则后执行。

8. 异常、降级与安全边界

  • 日报未结算、字段缺失或重复：阻止生成正式草案并提示缺失项。
  • 策略比例不闭合、范围重叠、渠道覆盖不完整或存在未覆盖范围：阻止提交；渠道配置作为最终路由兜底，系统必须在发布前校验所有有效渠道均有路由。
  • DCC 导入失败或超时：保留草案，不能显示为已生效；支持重试但需幂等。
  • Agent 生成失败或输出不符合 Schema：沿用最近有效版本，记录失败原因并通知运营，不影响已发布策略继续执行。
  • 实时接口不可用：沿用最近有效版本，记录风险，进入日级建议/偏差提示模式，不自动改变分派。
  • 发布后不可直接改写历史版本；修改必须复制为新版本。
  • 无法追踪下游转化结果时，只展示分派执行指标，不伪造转化闭环。
  • 迟到或修正数据只进入下一次草案计算，不改写已经发布版本的历史快照。

9. 本版本完整交付范围

本项目按一个完整版本规划，以下能力均属于本版本交付范围。外部系统接口、数据权限和联调进度是交付前置条件，不改变本版本的功能范围。

现有功能与新增能力边界：现有六类规则及固定比例分派继续保留。本方案需要在现有分配策略功能上新增低效对象配置、人工容量与缺口计算、受比例边界约束的调配建议、Agent 可解释建议，以及审核、版本发布和回滚联动；不能把这些新增能力视为现有系统已经支持。

11. 验收口径

  • 给定同一份已结算数据和同一版本参数，重复生成结果一致，或能解释随机性。
  • 所有建议行可追溯到数据日期、公式、权重、容量和规则来源。
  • 运营能够配置低效对象类型、指标、阈值、最低样本量和比例边界；未达最低样本量的对象不判为低效、不自动降低人工比例。
  • Agent 展示调整前后比例、触发条件及容量缺口；未经人工审核发布，不改变生效策略；调整不得突破比例边界。
  • 比例不闭合、范围冲突或数据缺失时阻止提交；样本不足时仅阻止该评分对象参与本次排名和比例调整，不阻止相关线索按现行规则分派。
  • 发布成功后，新任务能记录策略版本；导入失败不会误显示为生效。
  • 已发布版本不可被后续编辑覆盖，回滚可定位到上一有效版本。
  • 若实时接口未提供，系统明确显示“日级建议模式”，不宣称实时自动调配。
